### Phân tích
Ta thấy đây có thể là một bài heap. Các `node` có cấu trúc, được một mảng chứa các con trỏ trỏ đến các vùng heap được sinh ra từ `malloc()`

```c
typedef struct node
{
    size_t id, n;
    char data[0x10]; 
    void (*func_ptr)(char*); 
    size_t link[0x10]; 
} node;
```


Mỗi node có id độc nhất của nó, được lưu trên mảng `0x10` phần tử.
Có vùng lưu data `0x10` bytes
Một ô nhớ lưu địa chỉ của hàm `(*func_ptr)`, lúc khởi tạo node sẽ được đặt vào đó hàm puts
```c
void node_method(char words[])
{
    puts(words);
}
```

Đồng thời, trong code có hàm `call_me()` sẽ lấy flag từ hệ thống:
```c
void call_me()
{
    system("cat flag");
}
```

Vậy từ đây ta có thể thấy mục tiêu ban đầu sẽ là bằng cách nào đó ghi đè địa chỉ của hàm `call_me()` vào ô nhớ của `(*func_ptr)` trên node.

Ta chỉ có các option:
- Create node
- Link node
- Save data

Không có các tùy chọn chỉnh sửa, xoá note 
=> Không có UAF, double free, bin poisoning,...

Hàm đọc data duy nhất trong hệ thống cũng không cho thấy khả năng heap overflow

Hàm đọc data vào sử dụng `read()`, có buffer ptr và `count = 0x10` đầy đủ.

Tuy nhiên cách đọc data của hàm có lỗ hổng:

```c
tmp->func_ptr("Data: ");
read(0, tmp->data + strlen(tmp->data), 0x10);
tmp->func_ptr("Done!");
```

Hàm `read()` gồm 3 args là:
- `fd` mode của hàm
- `buffer`
- `count`

Ở đây địa chỉ của buffer có cộng thêm `strlen()` của xâu đã được lưu trên vùng data của node đó.

Lợi dụng điều này, ta có thể ghi 2 lần, mỗi lần không quá `0x10`, để ta có thể đẩy phần data thừa sang vùng nhớ của nơi lưu địa chỉ hàm của node.

Lý thuyết như sau:
```
0x0000000000000000      0x00000000000000b1
0x0000000000000000 id   0x0000000000000000  n
0x0000000000000000      0x0000000000000000  16 bytes char data
0x0000000000401276 func 0xffffffffffffffff  link
```
Ta thấy ô nhớ của `(*func_ptr)` nằm ngay dưới vùng data, có thể bị ghi đè lên.

Khi gọi đến hàm `read()`, data sẽ được ghi vào:
```c
tmp->data + strlen(tmp->data)

// tmp là con trỏ node
```
Lúc đầu chưa có data nào trên node, vì vậy kết quả của `strlen(tmp->data) = 0`

Sau lần đầu ta ghi vào data `x` (không quá `0x10`) bytes, vị trí ghi tiếp theo sẽ được đẩy lên thành 

```c
// strlen(tmp-data) = x

tmp->data + strlen(tmp-data)
// => tmp->data + x
```

Từ đó ta tiếp tục gọi đến hàm `read()` để được ghi tiếp `0x10` bytes tiếp theo
